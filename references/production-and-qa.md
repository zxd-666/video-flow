# 制作与验收

仅在用户确认文案、声音形式和视觉风格后读本文件。以确认稿为内容基线，制作代码驱动的配乐字幕版或 API 口播版；网络图或 AI 生图只是静态素材，不替代代码编排的镜头。

## 开工与工程

记录确认稿版本、段落 ID、来源、当次约定的时长/画幅/平台、声音形式和视觉风格。先检查本机工具与素材；优先读取已安装 `huashu-motion` 的 `SKILL.md` 和所需的 `references/contract.md`，使用本地 `om` CLI，运行 `om doctor`。使用该后端时遵守其项目契约和适用的导演、声音、验证文档；这份 Skill 的“文案与方案确认后开工”边界优先。若缺少必要能力，明确说明，继续完成能做的准备，不伪造媒体文件。

按项目保存：确认版 `script.md`、事实来源 `research.md`、调研原件与 `research/evidence-index.md`、导演方案、统一时间线、场景工程、字幕或屏幕文案、静态素材与出处、成片。API 口播版另存供配音的纯文本与最终旁白音频；配乐字幕版保留音乐和音效素材。保持段落/场景稳定 ID；每个媒体文件可以追回确认稿段落。使用本地可编辑源文件，不把个人凭据写进工程。

## 选定风格后直接制作

使用用户审稿时选定的“清爽纪实 / 纸感拼贴 / 深色技术台”或自定风格直接进入逐镜头制作。不再预制三版视觉方向，也不把短样片作为全片制作的固定前置步骤；用户明确要求试看时，按已选风格制作所需片段。选定风格定义材质、构图和运动语言，不替代当前主题的具体镜头设计。

找得到合适参考时，先拆成可执行参数：主色与明暗、字体层级、主体位置、前中后景、字幕、镜头时长、转场和声音落点。用这些参数创作本题材自己的画面，不直接套用参考片的素材、构图和叙事。没有参考时，从真实资料与内容机制生成视觉母题。视觉母题负责串起镜头，不要求主体物件和动作在每一段都相同。

先写简短 `treatment.md`：开头钩子、事实证据、解释过程、转折和结尾行动的情绪与信息节拍；统一视觉母题、字幕角色和声音层次。再建立逐镜头表：`段落/确认文案/时间 → 本镜要解释的关系 → 可见物件与有意义的动作 → 真实证据资产 ID 或“示意” → 景别/镜头运动/时长 → 字幕和声音提示 → 下一镜如何接续`。API 口播版填音频实测时间，配乐字幕版填阅读时长与音乐落点。每次切换要让观众多理解一步；镜头运动要引导注意力，不为动而动。中段尤其检查：连续两镜若只是同一机柜、图标或卡片换字，改为内容对应的过程、对比或边界揭示。

画面动作应表达其内容：请求流进入表示负载，分支与回收表示验证，局部放大表示深入证据，拉远表示关系汇总，划掉或收起表示被排除的方案。借用外部风格时只学这种叙事语法，不复刻其样片故事、素材和镜头。真实截图负责把观众带到可核查的资料现场；对模型内部、未公开实现或推理过程的画面用明确的“示意”标记，不把想象画成真实工程结构。

## 按声音形式定时间

**配乐字幕版**不生成人声。按确认稿提炼短句与必要的画面标注；先定每段的最短阅读时间和动作落点，再编配背景音乐和音效。字幕在此模式下承担讲解，不是逐字口播字幕；切勿把长稿整段压在画面上。

**API 口播版**调用已可用且获授权的语音生成 API 生成人声。用户若指定服务和音色则优先按指定方案；未指定时核查当前可用 API 并选择合适的中文语音方案。普通文本模型不等于语音合成接口；具体 API 的能力、价格、许可和调用方式以制作时的官方文档为准。不得擅自改用系统 TTS 或纯配乐。涉及新付费服务、个人声音样本或账号配置时，先取得相应授权。Key 仅在运行时从系统密钥管理器或已注入的进程环境读取；不得把真实值写入 Skill 文件、工程、命令、日志或交付包。

API 口播版先用一小段确认稿试听，至少覆盖开头情绪句、一个技术词和普通解释句。比较自然度、情绪力度、断句、发音、音色一致性与可用成本；选定后记录服务/模型、音色、参数、生成日期和音频文件，方便复现。长稿按段落生成时保持相同参数，检查段间音量、语速和音色是否跳变。`huashu-motion` 可用时，外部 API 音频按 `om voice --audio` 导入；先核对与确认稿一致，再对齐字幕。词提示的精度取决于 TTS/ASR 路径，按实际输出说明。

用一份可编辑时间线作为镜头、字幕/屏幕文案、音乐和音效提示的共同来源，关联段落 ID、起止时间、关键词和证据资产 ID。API 口播版按最终音频确定时间，语音有停顿、重录或删句时同步更新；字幕以听到的内容为准，不能以按字数平均分配的时间代替试听核对。配乐字幕版按阅读速度、信息密度、动作和音乐节拍安排时间，并在正常播放速度下复核。按需要布置与可见动作对应的音效、音乐和有意的短暂停顿；口播版优先保证人声清楚，音乐在人声下适当降低。

字幕/屏幕文案单独定视觉规范：字体、字号层级、字色/强调色、描边或底衬、行宽、断句、出现与退出方式、安全区。口播版跟着语义和呼吸走，配乐字幕版给每句足够阅读时间；都不拆英文词、不用超大的固定黑框长期遮住主画面。分别检查浅底、深底和信息最密的一镜；好看不能以降低可读性为代价。

## 画面与素材

按“观众此刻需要看到什么才能理解这句话”规划场景：标题、关键词、数字、流程、示意、产品 UI、对比、引用、真实截图、静态照片/插图。先从 `research/evidence-index.md` 挑选与该句直接相关且可用的原始画面；在代码里安排聚焦、放大、标注和足够的阅读停留，同时保留能让观众认出来源的上下文。信息图、图表、流程和文字在代码中绘制；照片或插画作为工程资产导入。网络素材保留原始 URL、作者/许可信息及使用说明；不确定可用时换成自制示意或其他可用资产。AI 生图要记录提示与生成版本，并人工检查清晰度、文字、事实暗示与水印；它不能充当事实证据。用户提供的素材保持其原意。

动效服务于解释：变化与口播的关键字或屏幕文案的语义落点相连；给重要信息足够停留时间。避免把整支片做成轮播幻灯片，也不为每一句话硬配一张图。视觉风格可以统一，镜头内容必须随讲解变化；每个中段转折至少改变一次观众正在看的关系、对象或视角，而非只改标题。画幅、字号和字幕安全区按目标平台调整。

每镜先写清物体的动作和它解释了什么，再选构图与景别。画面至少有可辨认的主物件与空间层次；特写、全貌和局部变化轮换。阅读时可以稳住镜头，转折时通过物件变化、遮挡揭示或镜头调度推进；仅给背景加流动光点不能替代内容动效。API 口播版的情绪钩子须试听，不把“文字夸张”误当成“声音有情绪”。

结尾画面落实确认稿里的干货：展示可搜索或可访问的原始资料入口、建议阅读的部分，以及与讲解内容一致的行动要点。手机竖屏观看时也要能暂停看清；不要只放一个无法辨认的长 URL 或一闪而过的二维码。

## 验证与交付

使用后端的静态和视觉检查；`huashu-motion` 可用时至少运行 `om check`、查看关键时刻 `om still`、`om render`、对最终文件运行 `om qa`。看首屏、最密信息画面、场景转换后第一秒及结尾；按正常速度观看并听完整成片，检查声画落点、字幕/屏幕文案停留。API 口播版另查人声清晰度、实际语音与字幕、镜头时间线；必要时用 ASR 辅助找漏字和错读，并人工确认。用 `ffprobe` 或等效工具检查视频/音频轨、画幅和真实时长。逐个检查入镜截图的来源、截取语境、日期、许可与画面标注，抽查关键事实在画面上的数字/措辞与原始材料一致。

全片渲染前输出覆盖钩子、机制、转折、密信息与结尾的关键帧总览，检查文字遮挡、色彩、字幕和景别变化，并据此修正；关键动作附近增加密集抽帧，检查转场与音效是否落在同一语义点。再按镜头表逐段核对“讲解表达了什么、画面实际展示了什么”。中段抽取相邻关键帧比较：如果画面主体、运动和景别连续重复，却只换文字，就重做这段。渲染后再从实际 MP4 抽帧复查，并检查黑帧、突兀闪烁、长静止时段和字幕停留。静止画面若用于阅读可保留；若内容没有推进，修改镜头或物件动作，不以装饰性移动掩盖。记录实际改动与剩余问题，不把通过自动检查等同于审美验收。

专门暂停检查结尾：资料名称/路径能照着找到，行动要点足够具体且与已核查事实一致，字大小和停留时间适合目标画幅。交付的来源清单保留直接链接，方便观众继续阅读。

交付 MP4、字幕或屏幕文案文件、可编辑工程和素材/来源清单；说明声音形式及音频来源、实际时长、画幅、已跑的检查与仍未验证的部分。只有工程可渲染、成片可播放且内容验收完成，才报告“视频已完成”。不自动上传或发布，不自动把单支影片反馈写成长期用户偏好。
