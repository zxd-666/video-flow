# 研究与脚本

仅在研究、撰稿和脚本修改时读本文件。文案、声音形式和视觉风格确认前，可保存真实网页截图、原始图片和资料副本作为调研证据与候选视频素材；不制作配音、AI 图片、动画或视频。

## 从主题到可讲的观点

先确定观众看完应理解的一件事，再安排“问题—解释—证据—结论”的顺序。题目过宽时主动收束到一个可讲清的角度，并把取舍告诉用户。默认写简体中文、面向一般关注该主题的观众；若无时长要求，先以约 2–3 分钟为写稿目标，按内容密度调整并标出估计。发布平台未知时先不把脚本绑死在某个画幅。

面向短视频平台时，把这“一件事”写成一句可复述的核心判断。开头约 2 秒内先给最有张力的事实、问题或结论，后面约每 10–15 秒安排一个有新信息的转折或追问；这些是节奏检查点，不要求机械切镜。逐段检查讲解内容和画面是否都在推进核心判断，并保留已核实的边界与结尾的资料入口。

把资料分成三类：

1. **当前事实**：发布日期、版本、产品能力、价格、政策、数据、人物职务等。必须核查最新状态，记下资料日期与事件日期。
2. **稳定背景**：概念和原理，可用已有知识辅助解释；关键或非显而易见的背景仍找可核查来源。
3. **分析判断**：写清推理依据，用“这意味着”“我的判断是”等语言与事实区分；有反例或争议时保留边界。

优先打开原始来源全文或原始数据，不只看搜索页、转载标题和模型摘要。冲突信息追到各自统计口径或更新时间。找不到可靠依据时缩小表述、删除该断言或标为待核，不编数字补空白。若网络不可用，说明无法完成“最新信息”核验，交付清楚标记局限的草稿，不把它称为已核实的近期解读。

## 调研时同步留存视觉证据

读到可能入镜的资料就及时留存，不等写完脚本再找。按“能否证明讲解中的一个关键事实、能否让观众看清原始入口”筛选，优先官方公告标题与日期、仓库目录和关键文件、产品真实界面、论文图表及原始数据；不要为每句话凑图。对会变动的页面，保存当时的原始截图或可取得的原始文件，并记录访问时间和页面所标发布日期。截图须保留足以辨认来源的标题、域名、上下文与必要日期；可另外做裁切副本用于画面，但保留未修改原件。

项目内用 `research/assets/` 保存调研原件，用 `research/evidence-index.md` 记一行一个候选：`资产 ID｜段落 ID / 断言｜原始 URL｜来源/作者｜发布日期与获取时间｜本地文件｜截图展示的内容｜使用许可/待核事项｜计划入镜方式`。网页截图、下载的原始图片、视频画面截帧要标明各自类型；来源链接与截图不能互相替代。无法保存或不宜保存时，在索引写精确入口和原因；不要声称已经取得文件。用户审稿时给出关键候选的缩略预览或路径，说明哪些只是参考、哪些拟放进成片。

真实截图只是“该页面在获取时显示了什么”的证据；数字和结论仍需追到原始材料核实。不得把模拟 UI、重绘示意或 AI 生图冒充真实截图。引用原文与数据时保留语境和统计口径；截图若含个人信息、账号内容或受限资料，先判断是否有权留存和展示，必要时不用。核查许可、署名和平台条款；调研阶段保存的候选不自动获得发布使用权，无法合理使用时改用可授权素材或代码绘制并清楚标“示意”。

## 审稿交付物

可在聊天中交付；长稿可保存 `script.md` 与 `research.md` 供审阅。结构保持简单：

- **创作假设**：受众、拟讲清的核心观点、预计时长、表达风格；未确定项标为默认。
- **内容稿**：`S01`、`S02`……稳定段落 ID；先写完整、可口播的讲解文本，便于核查内容。若用户选配乐字幕，制作阶段再提炼成短句屏幕文案，不逐字铺满画面。开头尽快给问题或结论，中间每段推进一个意思。结尾明确告诉观众到哪里看原始信息、先看什么，以及能用于判断或行动的 1–3 个具体收获；即使开头情绪强烈，结尾也要落到可核查、可使用的内容。首次出现的术语用大白话解释。数字要可听懂，不堆长串参数。
- **来源映射**：把支撑关键断言的直接链接、资料发布日期、事件日期及适用范围对应到段落 ID。注明“官方说法”“原始数据”“媒体报道”或“分析推断”，不要把宣传口径当作独立测量结果。
- **画面意图**：每段一句话指出要解释什么，可写“无需专门配图”；可引用证据索引里的候选资产 ID。结尾标明要展示的资料名称、可搜索路径/链接和行动要点，并安排足够阅读时间。此时仅收集真实资料，不建视频工程。
- **视觉证据目录**：交付已留存的关键截图/原始文件及索引；注明获取失败、许可待核或仅供参考的素材，避免把候选图误认为已能发布。
- **制作选择**：随审稿稿一次列出两个声音选项——①配乐字幕：无口播，背景音乐和音效承载节奏；②真人演说（API 配音）：调用语音生成 API 产生人声讲解，可配低音量音乐。再列出“清爽纪实 / 纸感拼贴 / 深色技术台”三种风格的简短说明与针对本主题的推荐，允许用户自定风格。请用户一起确认文案、声音形式和风格；已明确指定的项不重复询问。若只回复“ok”，视为确认文案，继续询问尚未选择的声音形式或风格。

审稿稿中的来源标记和画面提示不属于最终讲解文案。选真人演说（API 配音）时，确认后导出纯口播文本供配音，按段落 ID 建立映射；不要让标题、URL、括注和来源说明被念出来。选配乐字幕时，按段落 ID 提炼屏幕短句，保留内容含义和事实边界。生产中的实质内容改动回写脚本版本并重新确认受影响段落。
